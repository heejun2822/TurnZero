# TurnZero 구현 기준과 개발 순서

> **보관 판본 · 2026-10-28 재편 전.** 현재 규칙은 [DevelopmentPlan.md](../../DevelopmentPlan.md), 현재 작업은 [Development.md](../../Development.md)를 따른다. 이 판본은 당시 기록으로 유지한다.

## 현재 구현 범위

첫 개발 묶음인 3D 로컬 전투 프로토타입을 구현했다. 원본 `Plan.md`의 정식 기획과 아래 임시 규칙을 구분한다.

- XZ 평면의 입체 타일로 구성한 고정 대칭 맵, 기지 배치, 플레이어당 동일 캐릭터 4명.
- 원근 카메라, 시점 회전·확대·축소, 조명·그림자가 적용되는 임시 3D 캐릭터와 기지 모델.
- 이동·기본 공격·무료 대기, AP 예약·수정·취소, 공용 준비 시간.
- 단계별 동시 판정, 시야, 마지막 관측, 관측 가능한 전투 결과.
- 전멸 또는 기지 파괴로 승리, 동시 패배는 무승부, 재시작.
- 양측 시점 전환, 마우스·터치 입력, 가로·세로 화면 배치.
- 턴별 명령·초기 상태·결과를 저장하고 같은 판정을 재현하는 개발용 기록.

참고 이미지에 맞춰 카메라 기본 회전을 정면으로 바꾸고 높은 시점에서 필드를 넓게 보여준다. HUD는 상단 기지·턴·타이머 바, 오른쪽 캐릭터·액션·명령 미리보기·장비·READY 패널, 하단 4인 초상화 카드와 AP로 구성한다. 선택과 이동 경로는 청록색, 공격은 빨간색으로 표시한다. 모든 UI 문구는 영어다. SKILL·ITEM은 아직 비활성이며 장비와 역할별 이름은 외형 표시다.

가로 화면은 참고 이미지의 배치를 사용한다. 세로 화면은 필드를 위쪽에 두고 카드 목록과 명령 패널을 아래쪽 두 열로 나눈다. 초상화·아이콘의 생성 기록은 `Tools/Art/README.md`에 있다.

온라인, 스킬, 아이템, 부활, 필드 편집, 계정·재화는 아직 구현하지 않는다. 아래 단계별 착수 조건을 먼저 충족해야 한다.

## 검증용 수치표

`Assets/ProjectFiles/Prototype/Scenes/Battle.unity`의 `Battle Session` 오브젝트에 있는 `BattleController` 컴포넌트에서 Rules를 조정한다. 플레이 중에는 경기 생성 시 복사한 규칙을 사용한다. 수정 후 새 경기로 시작한다. 맵 크기는 배치된 `BattleMapView`를 기준으로 한다.

| 항목 | 임시값 |
|---|---|
| 전체 맵 | 가로 16 × 세로 24. 자기 필드 16×10, 중립 16×4, 상대 필드 16×10 |
| 기지 배치 | 자기 필드 가장자리 한 칸 제외. 중립 배치 불가. 상하좌우 4칸의 생성 공간 확보 |
| 캐릭터 | 동일한 캐릭터 4명, HP 3 |
| 기지 | HP 8 |
| 공격 | 피해 1, 상하좌우 거리 2 |
| 이동 | 상하좌우 한 칸 |
| 시야 | 기지와 살아 있는 캐릭터 기준 상하좌우 거리 2 + 해당 턴의 유효한 공격 대상 칸 |
| AP | 첫 턴 4, 이후 턴 시작 회복 4, 상한 8, 잔량 이월 |
| 행동 비용 | 이동 1, 공격 2, 대기 0 |
| 준비 시간 | 공용 30초 |
| 판정 표시 | 0.75초, 입력 잠금. 종료 후 다음 턴의 준비 시간 시작 |

캐릭터는 기지 기준 +Z·+X·-Z·-X 순서로 번호가 부여된다. 규칙의 Cell.X/Y는 월드 X/Z에 대응한다. 상대편도 동일한 전역 좌표를 사용하며, P2는 +Z 방향 필드를 사용한다. 카메라 회전은 규칙 좌표에 영향을 주지 않는다.

## 임시 판정 규칙

1. 준비 중 캐릭터마다 하나의 명령만 보유한다. 새 명령은 이전 명령과 예약 AP를 교체한다. WAIT / CANCEL은 명령을 제거한다.
2. 잠금은 자기 명령의 수정만 막는다. 실제 확정과 AP 차감은 준비 종료에 양측 함께 수행한다. 두 명이 잠가도 타이머는 계속 흐른다.
3. 시간 만료 시 현재 명령을 확정한다. 미지정 캐릭터는 대기한다. `ADVANCE TURN`은 개발 검증용 조기 판정이다.
4. 이동은 우선순위 2. 같은 목적지의 모든 이동은 실패한다. 단계 시작에 캐릭터나 기지가 점유한 칸으로는 이동할 수 없다. 자리 교환·뒤따라 이동도 실패한다.
5. 이동 후 시야를 갱신한다. 공격은 우선순위 3이며 캐릭터 또는 기지 ID를 대상으로 한다. 지정 시 현재 시야·사거리 안의 적만 선택할 수 있다.
6. 공격 실행 시 이동 후 위치·시야·사거리를 다시 검사한다. 대상이 이동했어도 여전히 유효하면 공격한다. 실패한 이동·공격의 AP는 환불하지 않는다.
7. 유효한 공격 피해는 모두 모아 동시에 반영한다. 같은 단계에서 죽는 캐릭터도 자신의 공격을 수행한다. 사망체는 다음 이동의 점유·시야 제공에서 제외한다.
8. 공격 단계 종료 후 기지 파괴·전멸을 검사한다. 양측 패배 조건이 동시에 성립하면 무승부다. 종료된 경기에는 새 명령과 AP 회복이 없다.

## 정보 공개와 마지막 관측

- 내 캐릭터·기지·HP·AP·명령은 공개 정보에 포함한다. 상대 AP·명령은 포함하지 않는다.
- 적 위치·HP는 현재 시야에 있을 때만 최신 정보를 제공한다. 적 기지 HP도 같은 기준이다. 승패는 양측에 공개한다.
- 상단 적 기지 HP를 모르면 `?`, 마지막 관측만 있으면 수치에 `*`를 붙이고 회색 막대로 표시한다.
- 시야를 잃은 적의 위치·HP·관측 턴은 복사본으로 유지한다. 현재 상태에 연결해 갱신하지 않는다.
- 현재 시야 밖에서는 적의 실제 모델을 숨기고 마지막 관측 위치·당시 HP·관측 턴을 마커로 표시한다. 마지막 관측 위치가 현재 위치인 것처럼 갱신하지 않는다.
- 자기 필드는 탐색한 상태, 중립·상대 필드는 미탐색 상태로 시작한다. 현재 시야와 탐색 기록은 플레이어별로 분리하며 시야를 잃어도 탐색 기록은 유지한다.
- 미탐색 타일은 지형 종류와 관계없이 동일한 검정 계열 바닥으로 격자와 필드 경계를 표시하며 조형물·선택 테두리는 숨긴다. 탐색한 타일은 원래 색의 30% 밝기로 표시하며 현재 시야의 타일은 정상 표시한다.
- 기본 공격의 유효한 대상 칸은 공격한 플레이어에게 해당 턴 동안 공개한다. 판정 표시 구간 0.75초가 끝나 다음 턴이 시작되면 임시 공개는 만료되고 탐색 기록만 유지한다. 준비 시간 30초는 판정 표시가 끝난 뒤 시작한다.
- 스킬 실행은 아직 없으며, 스킬도 같은 지점 공개 함수 `BattleState.RevealCell`을 사용할 수 있다. 공격 예약·취소·실행 실패는 시야를 공개하지 않는다.
- 마지막 관측 칸을 다시 보았는데 해당 적이 없으면 흔적을 지운다. 적을 다시 보면 최신 위치·HP로 바꾼다. 관측한 사망도 반영한다.
- 이동 결과에서 적이 시야 밖으로 나가면 목적지 대신 시야에서 사라졌다는 결과만 제공한다. 보이지 않는 적의 실패 명령은 공개하지 않는다.
- `SAVE REPLAY`의 파일은 양측 전체 정보를 포함하는 로컬 개발 자료다. 온라인 클라이언트로 전송하면 안 된다.

게임 판정 코어는 Unity와 무관한 C#이다. 전체 상태와 명령으로 새 상태를 계산하고, 화면은 플레이어별 `PlayerView`만 읽는다. 애니메이션과 물리 충돌은 판정에 사용하지 않는다.

`Battle.unity`에는 고정 맵, 캐릭터 8명과 기지 2개, 마지막 관측 마커, 카메라, HUD와 입력 시스템을 프리팹으로 미리 배치한다. `BattleController`는 경기 데이터와 입력 흐름만 관리한다. Play와 재시작은 씬 오브젝트를 다시 생성하지 않는다.

`BattleMapView`·`BattleTileView`는 좌표·시야·강조를, `BattleActorView`는 배치된 모델의 위치·라벨·활성 상태를 담당한다. `BattleWorldView`는 공개 정보에 있는 살아 있는 오브젝트만 표시하고 시야 밖 적의 모델과 선택 Collider를 함께 비활성화한다. `BattleLastSeenView`는 복사된 HP·위치·관측 턴만 표시하며 Collider가 없다. `PhysicsRaycaster`와 `BattleWorldTarget`은 마우스·터치 입력을 같은 경로로 전달한다.

상단 바·명령 패널·캐릭터 카드·AP 패널·툴바는 별도 프리팹과 View 스크립트로 나눈다. `BattleHudView`는 공개 정보를 각 View에 전달하고, `BattleHudLayout`과 `BattleCameraRig`는 가로·세로 화면의 남는 영역에 3D 필드를 맞춘다. 임시 모델·UI 생성은 편집기 전용 명시적 재생성 도구에만 남아 있다.

고정 필드는 `2D Tilemap Extras`의 `GameObject Brush`로 편집한다. `Field Grid` 아래 Allied Field·Neutral Field·Enemy Field 세 Tilemap만 저장한다. 전체 전역 좌표는 X 0–15, Y 0–23이며 중립은 Y 10–13이다. 팔레트는 바닥 3종과 TreeTile·RuinedWallTile을 제공한다. 조형물 포함 타일도 바닥 하나와 선택 대상을 함께 가진다. 런타임은 세 레이어의 모든 바닥을 읽고 시야·강조를 갱신하며, 빈 칸·중복·범위 밖·잘못된 레이어·격자에서 벗어난 배치를 검사한다. 주변 바닥·외곽 조형물·Foundation은 제거했다. 나무·벽·지형 종류는 현재 외형만 구분하며 이동·시야 차단 규칙은 추가하지 않았다.

## 개발 순서와 착수 조건

| 단계 | 작업 | 완료 또는 착수 기준 |
|---|---|---|
| 0 | 최소 규칙·수치표 | 위 임시 규칙으로 결과를 설명할 수 있음 |
| 1 | 맵·배치·입력 | 양측 4명 배치와 마우스·터치 명령 지정 |
| 2 | 로컬 경기 | 준비·AP·이동·공격·시야·승패·재시작 연결 |
| 3 | 기본 검증 | 자동 테스트, 기록 재현, 실제 플레이 후 수치 조정 |
| 4 | 온라인 기본 대전 | 네트워크 도구·호스팅·비용·복귀 정책 확정 후 2인 방 구현 |
| 5 | 전투 확장 | 대표 스킬 → 상태 효과 → 소비 아이템 → 장비·강화 → 부활 → 다중 턴 설치 |
| 6 | 편성·필드 커스텀 | 캐릭터 역할·특수 타일·편집 제한·경로 유효성 확정 |
| 7 | 계정·재화·뽑기·진화 | 영구 성장과 경기 반입 관계 확정 후 보유·보상·합성 저장 |
| 8 | 출시 | 화면 방향·카메라·지원 OS·최소 기기 확정, 아트·음향·튜토리얼·실기기 검증 |

온라인은 모든 콘텐츠를 만든 뒤로 미루지 않는다. 기본 전투 검증 후 서버가 명령·AP·턴 마감·판정을 검증하고 각 플레이어에게 관측 가능한 정보만 전송한다. 첫 온라인은 방 생성·참가로 제한하고 자동 매칭·랭크는 별도 기획한다.

## 확장 전에 정할 기획

- 전멸 즉시 패배와 부활을 어떻게 연결할지, 부활의 행동 주체·위치·비용·타이밍.
- 은신·기절·회복·보호막의 우선순위와 시작·종료, 예약 명령에 대한 영향.
- 아이템 획득·장착·강화의 행동/AP 소비, 인벤토리 주체, 장비 교체와 사망 반환.
- 텔레포트 설치 중 이동·다른 행동·사망·취소 시 처리.
- 뽑기 장비를 경기 시작부터 반입하는지, 경기 내 생성 후보를 해금하는지.
- 등급·진화가 전투 능력치를 높이는지와 대전 공정성 정책.
- 필드 연결 방향, 특수 타일 비용, 기지 접근과 생성 공간 검증.
- 장시간 대기·도주에 대한 턴 제한·무승부·항복. 현재 프로토타입에는 자동 턴 제한이 없다.
- 앱 백그라운드·연결 중단·재접속·늦은 명령·중복 명령의 온라인 처리.
- 모바일 대상 OS·최소 사양·최소 터치 크기와 실제 기기에서의 가독성.

## 검증

- Unity Test Runner의 EditMode: 배치, 예약·취소·AP 상한, 마감·잠금·지난 턴, 충돌·자리 교환·뒤따라 이동, 공격 대상 이동, 상호 처치·기지 동시 파괴, 입력 순서 독립성, 시야·정보 복사·마지막 관측, 기록 재현.
- PlayMode: 배치부터 판정·재시작까지 연결, Input System의 실제 마우스·터치 이벤트로 3D 타일 배치와 캐릭터 선택, 원근 카메라·회전·줌, 3단계 안개·조형물 표시, 시야 밖 실제 적 숨김과 마지막 관측 마커.

- `BattleState.RevealCell`은 행동 판정에서 공통으로 사용하는 턴별 지점 공개 함수다. 임시 시야는 명령을 재판정하여 재현하므로 기존 전투 기록 JSON 형식에 추가하지 않는다. 스킬 실행과 나무·벽의 시선 차단은 아직 제공하지 않는다.
