## 1. 현재 위치

로컬 인게임은 한 기기에서 양측을 바꿔 조작하며 배치 → 준비 → 판정/재생 → 종료 → 재시작을 시험하는 단계다. 12×20 필드·5종 캐릭터·기본/스킬/장비 행동·부활·제작·관측·HUD가 연결되어 있다.

후속 기획 결정이 현재 소스에 모두 반영된 상태는 아니다. 현재 실행 프로필을 최신 명세의 최종 동작으로 간주하지 않는다. 규칙은 DevelopmentPlan.md에서 읽고, 소스와의 차이는 이 문서에서 관리한다.

| 확인 범위 | 현재 연결 | 남은 범위 |
|---|---|---|
| 편성·필드·배치 | 로컬 씬, 필드 SO 3개, 장비 5칸 UI, 기지/각 5명 수동 배치 | 중복 없는 장비 1~5종 편성, 필드 편집 UI/런타임 저장, Q-20 배치 조건 |
| 턴·AP·전투 | 예약·비용·칸별 이동 루프·공격 피해 수집·순차 큐 재생 | 아래 PT 차이 표의 실제 판정/재생 경계 정합화 |
| 스킬·상태 | 은신·고정 전용 필드와 불타는 지대 | 공통 상태 효과 시스템, 최신 지대 발동·간파·사망/부활 경계 |
| 아이템·장비 | 제작 재료와 3종 장비, 제작/교체, 포털·교환·시야 구조물 | 최초/동시 접촉과 즉시 제거, 설치/교환 경합, 강화/소비 콘텐츠 |
| UI·입력 | 카드·상세·25칸 AP·인벤토리·도움말, PC/터치·가로/세로 | 최종 입력 Q-18, 공격별 HP·획득/AP 효과, 실기기 사용성 |
| 온라인·성장 | 별도 구현 근거 없음 | Q-21·Q-22 범위 확정 후 착수 |

실행은 [LocalPlaytest.md](LocalPlaytest.md), 현재 코드의 책임/호출 관계는 [GameArchitecture.md](GameArchitecture.md)를 따른다. 표시명·모델은 테스트용이며 정식 콘텐츠 이름으로 확정하지 않는다.

- 배치 제한시간·양측 배치 순서/상대 공개 시점·기지의 ‘빈 타일’에 포함되는 점유 제한은 Q-20과 함께 보완한다.

- 결과 UI와 처치 AP 지급 효과의 세부 표시 순서, 자기 사망 캐릭터 포커스는 Q-18과 연결한다.

- 새로운 쿨다운 3 이상·상태 효과·피해/이동 기능을 추가하면 그 콘텐츠의 미정 기간·중첩·경계를 별도 정의한다.

## 5. 다음 개발 작업

현재 확정된 범위부터 아래 묶음으로 구현/검증할 수 있다. 새 온라인/계정 도구나 미정 콘텐츠를 이번 문서 작업에서 선정하지 않는다.

| 공통 판정 정합화 | 페이즈 0~4, 예약 사거리/효과 범위, 실행/사망/쿨다운/AP·복합 승패 | PT-01·03·06·07·14의 관련 TC |

| 상태·지대·설치 | SYS-STATUS, 지대 자동 발동, 간파, 교환/설치 경합·종료 경계 | PT-04·05·09·10, TC-68~90·108~112·123~125 |

## 6. 문서 관리

규칙·수치 수정은 DevelopmentPlan.md, 결정 이유는 Decisions.md, 실제 실행 결과는 Verification.md에 기록한다. 이 문서에는 진행 상태와 남은 일을 남긴다.

GameArchitecture.md는 구조/호출 관계를 바꿀 때, LocalPlaytest.md는 실행·조작·데이터 편집 방식이 바뀔 때 함께 갱신한다. 이전 프로토타입은 회귀용 보관 자료이며 현재 규칙의 근거로 사용하지 않는다.
